# Bounded metadata write-ahead journal

Implementation source candidate only. NativeSwitchJournal is unused by Socket, YabCoreClient requests, EngineSwitchTransaction and ProductionAuthority. No native source, SDK, existing profile, current user file, preference, EOF policy or capability changes. This implements the local write-ahead storage portion of the separate durable journal plan, not a production switch/recovery service.

## What the component actually writes

A dedicated0700 directory contains a verified0600 .lock and at most64 fixed transaction slots, each with up to four immutable0600 revision files. Hash-slot collisions return capacity instead of evicting another original transaction. One O_EXCL .pending staging resource is allowed for the entire directory. Body<=256KiB, complete versioned envelope<=384KiB, at most256 original member identities and32 bounded command IDs (current v1 phases actually need at most2). There is no snapshot/form/storage/argv/environment payload, source PDF, URL, tokenized browser history or credential file.

The intent freezes original helper diagnostic kernel/code/birth evidence, original connection label, all original tab/profile/native browser/document IDs, target engine and settings baseline digest. Intent labels and decoded diagnostic Evidence do not supply an actual native CEF owner or prove the original source remains alive. Caller privacy classification is required; private/unknown classifications are refused. The writer cannot independently prove a canonical persistent profile association, so that native/store admission remains a future binding requirement.

The only v1 phases are intent -> reserveDispatchPending -> cancelDispatchPending -> unknown; loss may branch from any phase directly to unknown. All positive native approvals/drain/seal/capture/final release/destination-ready/install/settings phases are deliberately absent. An authenticated original-client callback bridge, reviewed native registry authority and expanded journal schema are required before adding those states. Caller boolean/decoded native-looking JSON cannot establish them. This prevents metadata storage from masquerading as native acceptance.

writeAhead records a unique exact command BEFORE a caller considers sending it. It performs no dispatch. Repeated command/reserve, incorrect phase, stale revision/digest and unknown state refuse. A stored local pending state is neither dispatch acceptance nor a native outcome. No commit API exists. settingsBaselineSHA256 is immutable diagnostic CAS context only; this component never writes application preferences.

sourceLost(helperEOF/helperParentDeath/sourceProcessLost/unreadableIdentity/nativeOutcomeUnknown) writes unknown while retaining all original intent/command metadata. Stale/absent cursor returns unknown, never retained. Already-unknown is idempotent and retains its first loss evidence; adding subsequent source liveness facts is future schema work. Unknown never auto-cancels/resumes/retires/retries/reconnects/recreates an owner or installs a destination. The helper-loss callback wiring itself is NOT in this packet. Until that wiring and exact runtime proof exist, no end-to-end loss handling is claimed.

## Actual storage/CAS protocol

Open and validate an already trusted parent directory FD, create/open only the dedicated normalized child name with no-follow/CLOEXEC, verify owner/mode/inode and fsync the parent for a new directory. Every operation checks the original lock inode/name/mode, then takes nonblocking exclusive flock. Busy refuses; other lock/IO uncertainty stops the object. Cross-process coordination depends on all legitimate writers using that original protected lock. Hashes detect corruption; they are not cryptographic authorization against another arbitrary same-UID process.

Read only via pinned dirFD/openat O_NOFOLLOW/CLOEXEC. Verify regular owner0600 nlink1, bounded exact size, complete EINTR-aware pread, same named inode and final size, and checked close. Canonical version1 body/envelope hashes, strict phase grammar, original immutable intent, contiguous revisions and prior digest links must all match. Unknown versions, corruption, links, missing intermediate revisions or contradictory phase chain are unknown.

A new revision is fully encoded BEFORE opening .pending O_CREAT|O_EXCL|O_WRONLY|O_NOFOLLOW|O_CLOEXEC0600. Verify exact inode, write all bytes, fsync file, verify again and close once. Then renameatx_np with RENAME_EXCL publishes only a NEW revision name, preserving all older evidence, and fsync the directory before returning stored. No target overwrite, truncation, unlink or eviction occurs. The installed SDK declares both openat Swift overloads and renameatx_np/RENAME_EXCL; actual shared Swift/POSIX execution remains required.

Any write/close/rename/dirfsync uncertainty returns unknown and poisons the writer. A leftover .pending record stops subsequent writers, including after a new process opens the directory. It is not adopted, deleted or replayed automatically. The fixed staging resource and fixed revision names bound old failed work. A valid latest pending record after a crash is still only an intent, never evidence native dispatch completed. No claims are made about power-loss storage-controller guarantees; file/directory fsync process-crash boundaries and actual filesystem fault behavior require acceptance.

## Dependencies and deliberate remaining gaps

NativePeerIdentity supplies an actual unused audit-bound socket/kernel/code reader with private live constructor. Its Codable Evidence may be persisted diagnostically but cannot recreate the live identity or a library-owned CEF owner. Before future production effects, the original live peer must be retained/reobserved and exact original helper/member/source-document authority must be independently checked. Current native logical frame process IDs still lack a production renderer OS-birth lineage API.

Current R1 EOF/parent-death handling can force-close originals and terminate the helper. A record never promises they survive it. Helper/native process loss remains unknown even when data was fsynced. Same-process native registry0054, anonymous snapshot FD and original actual owner are not recoverable by journal strings or a fresh factory owner. No replacement-peer resolver is implemented. Original-group commit, full mutation/storage fences, destination staging/data readiness, private encrypted payload policy and genuine WK/mixed authority remain active blockers.

Five authored Swift tests exercise actual temporary POSIX storage/CAS/reload, immutable old revisions, helper loss, stale cursors, crash staging, corruption/link refusal and private/repeated command rejection. NOT_RUN. Four Python structural/negative guard methods ran PASS; they are not filesystem, compiler, native or durability proof. Root must include these suites in the one combined prepared-artifact batch and preserve actual receipts. More crash-before/after each write/fsync/rename and concurrent-process lock/fault tests remain mandatory before production binding.
