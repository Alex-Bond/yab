## Implemented actual transport

Each original-native `switch.group.*` request is admitted only after actual `originalGroupReady`, then rechecks the SAME private counterpart object/helper factory/connection and bounded registry after the await. Request IDs are monotonic within the original connection nonce, never recycled from evicted history. UInt64 exhaustion refuses further dispatch.

The actual Socket creates a private write ticket hashing the exact frame INCLUDING newline. Client reserves its record and waiter/context before enqueue. The Socket verifies its own nonce, one-shot created ticket, frame length/digest and unchanged4MiB wire/8MiB output bounds before appending bytes. Each tracked frame stores its own prefix relative to the actual output buffer. Real Darwin.write results count ONLY the overlap with that frame, not bytes from an earlier queued task/global counter. Enqueued, allWritten, notEnqueued and partial/lost-unknown are distinct. allWritten is historical stream forwarding, never helper dispatch or applied native action.

A separate production reply ledger is checked BEFORE ordinary pending-continuation cancellation drop. Caller cancellation/timeout detaches its waiter, marks source/journal unknown BEFORE continuations resume, and leaves the exact ticket/context/request row. It sends no native cancel, retry, retirement, replacement or reconnect. The original raw response frame may later be correlated once and hashed; abandoned rows remain unknown and do not produce another UI/peer result. Duplicate responses cannot replace the first digest.

At most32 active/quarantined original request records exist. Unknown rows are non-evicting and poison further group requests on this original lane; ordinary routes remain connected. An actual envelope delivered to its original active waiter can release only its TRANSPORT slot, keeping a bounded64-digest diagnostic history. This permits more than32 successful immutable chunk reads without acknowledging/freeing any native group/resource registry. Late/abandoned/raw-error/malformed/source-lost entries are not treated as native complete/retained/released. No raw reply/snapshot payload is retained in the late ledger or logs.

The private context ties delivery to the actual admission counterpart/factory/connection. This is not a fresh post-reply kernel/image/doc validation and never claims a continuous native source/image lease. That stronger authority is explicitly absent below. Existing normal non-group requests retain their original cancellation/routing behavior. PDF43 event-origin and expectedPresence code is unmodified.
